| Commande Pathtrace | Paramètres et valeurs possibles | Explication courte | Exemple complet |
|---|---|---|---|
| `pathtrace --help` | `--help` : drapeau | Affiche les commandes disponibles. | `pathtrace --help` |
| `pathtrace install security` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope` : `provider`, `project` (défaut : `project`) ; `--presets` / `--no-presets` : accepter/refuser les presets fournisseur (choix interactif si absent) ; `--help` : aide | `provider` s'exécute depuis n'importe quel dossier ; `project` à la racine du projet. Les presets acceptés sont immédiatement appliqués. Une configuration existante n'est jamais remplacée. | `pathtrace install security --framework codex --scope provider --presets` |
| `pathtrace install security` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope project` (défaut) ; `--help` : aide | Active les règles du projet à sa racine. Aucun preset ajouté ; les règles fournisseur restent applicables. Les options de presets sont réservées à `provider`. | `pathtrace install security --framework claude-code --scope project` |
| `pathtrace install observe` | Cible facultative : `observe` (défaut), `security`, `all` ; `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope project` (défaut, seule portée Observe) ; `--help` : aide | Prépare la capture des traces à la racine du projet. Sans cible, `install` équivaut à `install observe`. | `pathtrace install observe --framework codex --scope project` |
| `pathtrace install all` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope project` (défaut, seule portée `all`) ; `--help` : aide | Active Security et Observe ensemble, à la racine du projet, en conservant les règles existantes. | `pathtrace install all --framework claude-code --scope project` |
| `pathtrace install security` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope provider` (explicite) ; `--presets` / `--no-presets` : choix initial ; `--help` : aide | Active les règles fournisseur depuis n'importe quel dossier. L'audit OTLP des décisions appliquées se configure dans le fichier YAML ; aucune commande Audit distincte. | `pathtrace install security --framework claude-code --scope provider --presets` |
| `pathtrace test` | `--tests` : fichier YAML obligatoire ; exactement l'un de `--trace` : fichier JSON ou `--latest` : dernière trace du projet ; `--report`, `--graph` : drapeaux (défaut : désactivés) ; `--output-dir` : dossier (défaut : `.pathtrace`) ; `--help` : aide | Teste une trace et affiche les résultats. `--latest` s'utilise à la racine du projet. `--graph` produit aussi le rapport JSON. | `pathtrace test --trace examples/trace-example.json --tests examples/path-tests-example.yaml --report --graph --output-dir .pathtrace` |
| `pathtrace run` | `--tests` : fichier YAML, dossier ou glob, obligatoire et répétable ; `--framework` : `codex`, `claude-code` (sinon YAML) ; `--project-dir` : dossier (sinon YAML, puis dossier de la suite) ; `--runner-arg` : texte, répétable ; `--timeout` : secondes ≥ 0.001 (sinon YAML, puis 600) ; `--trace-timeout` : secondes ≥ 0.001 (sinon YAML, puis 10) ; `--report`, `--graph`, `--fail-fast` : drapeaux (défaut : désactivés) ; `--output-dir` : dossier (défaut : `.pathtrace`) ; `--help` : aide | Lance les prompts et teste les traces. `--fail-fast` arrête au premier échec. `--graph` écrit aussi les rapports des scénarios ; `--report` ajoute le bilan de campagne. | `pathtrace run --tests examples/run-suite-example.yaml --framework codex --project-dir . --timeout 600 --trace-timeout 10 --report --graph --fail-fast --output-dir .pathtrace` |
| `pathtrace status` | `--help` : aide ; aucune autre option | Affiche les fonctionnalités, fichiers, règles et état de l'audit pour le dossier courant et chaque fournisseur. Aucun fichier modifié. | `pathtrace status` |
| `pathtrace uninstall` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope project` (défaut ; autre valeur : `provider`) ; `--help` : aide | Depuis la racine du projet, désactive son activation locale pour ce fournisseur. Conserve ses règles, les hooks partagés, les autres projets et la configuration fournisseur ; les protections fournisseur restent applicables. | `pathtrace uninstall --framework codex --scope project` |
| `pathtrace uninstall` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--scope provider` (explicite ; défaut sans option : `project`) ; `--help` : aide | Depuis n'importe quel dossier, supprime uniquement la configuration Security du fournisseur. Les configurations projet continuent de fonctionner. Les hooks partagés et les réglages natifs sont conservés. | `pathtrace uninstall --framework claude-code --scope provider` |
| `pathtrace uninstall --purge` | `--framework` : `codex`, `claude-code` (obligatoire) ; `--purge` : purge globale ; `--yes` : confirmation sans interaction (défaut : confirmation demandée) ; `--help` : aide ; incompatible avec `--scope`, `--yes` nécessite `--purge` | Depuis n'importe quel dossier, supprime tous les hooks Pathtrace et la configuration Security du fournisseur. Observe/Test et Security ne sont plus déclenchés dans ses projets. Conserve les hooks utilisateur, l'autre fournisseur et tous les dossiers `.pathtrace` des projets. Répétable sans perte supplémentaire. | `pathtrace uninstall --framework codex --purge --yes` |
| `pathtrace COMMANDE --help` | `COMMANDE` : `install`, `test`, `run`, `status`, `uninstall` ; `--help` : drapeau | Affiche l'aide d'une commande sans l'exécuter. | `pathtrace run --help` |
